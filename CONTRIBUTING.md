# Contributing to DSA Coach

## Before you start

- Read `README.md`, `PROJECT_SPEC.md`, `ARCHITECTURE.md`, and `ROADMAP.md`.
- Keep changes focused on one coherent outcome.
- Raise a proposal before introducing a major dependency, changing a domain model, or expanding MVP scope.

## Development standards

- Prefer clear, maintainable code over clever abstractions.
- Add or update tests for behavior changes.
- Treat authentication, authorization, learner data, and code-runner isolation as security-sensitive.
- Do not commit secrets, production data, or unlicensed problem content.
- Preserve accessibility and responsive behavior in UI work.

## Documentation changes

Update the relevant source-of-truth document in the same change when you alter product scope, an architectural decision, or roadmap priority. Include the rationale, not just the final choice.

## Pull requests

- Explain the user outcome and how the change was tested.
- Keep the description concise and identify any follow-up work.
- Ensure automated checks pass before requesting review.
- Use small, reviewable commits where practical.

## Code of conduct

Be respectful, constructive, and welcoming. Focus feedback on the work, assume good intent, and protect learner privacy.
